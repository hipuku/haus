## A form, from real components

Each control owns its own label, hint and error, so the composition is just
placing them. Nothing here re-implements a field, a label or a validation line.

<div style={{ maxWidth: 380, display: 'flex', flexDirection: 'column', gap: 'var(--haus-space-4)', padding: 'var(--haus-space-6)', margin: 'var(--haus-space-5) 0', border: '1px solid var(--haus-color-border-subtle)', borderRadius: 'var(--haus-radius-surface)', background: 'var(--haus-color-surface-default)' }}>
  <Callout tone="error">That email and password do not match.</Callout>
  <Input label="Email" placeholder="you@example.com" />
  <Input label="Password" type="password" hint="At least 8 characters." />
  <Checkbox label="Keep me signed in" />
  <Button tone="neutral">Sign in</Button>
</div>

The `Callout` carries meaning through `tone="error"`, the same `tone` word a
`Button` or `Badge` takes. The `Input` and `Checkbox` each render their own label
and reserve room for an error, so a form is composed by arrangement, not by
wiring accessibility together by hand.

## The vocabulary that makes it cohere

Four prop names carry the same meaning everywhere. A component narrows each to
what it offers and the narrowing lives in the type, so the compiler tells you
which values a given component accepts.

<div style={{ display: 'flex', flexDirection: 'column', gap: 'var(--haus-space-2)', margin: 'var(--haus-space-4) 0' }}>
  {[
    ['tone', 'What it means. neutral, info, success, warning, error. Shared by Button, Badge, Callout, Toast and the form controls.'],
    ['variant', 'Visual weight only, never meaning. On Button: primary, secondary, ghost, text.'],
    ['appearance', 'subtle or solid. The same surface treatment across Badge and Toast.'],
    ['size', 'sm, md, lg. Avatar keeps xs and xl as a documented extension.'],
  ].map(([name, description]) => (

      <code style={{ fontFamily: 'var(--haus-font-mono)', fontSize: 'var(--haus-type-mono-size)', color: 'var(--haus-color-ink-primary)', width: '7rem', flexShrink: 0 }}>{name}</code>
      <span style={{ font: 'var(--haus-type-body-sm-weight) var(--haus-type-body-sm-size)/var(--haus-type-body-sm-leading) var(--haus-font-sans)', color: 'var(--haus-color-ink-secondary)' }}>{description}</span>
    </div>
  ))}
</div>

Because `tone` means the same thing everywhere, one row of components reads as a
set rather than as five unrelated widgets:

## Why it holds: roles, not values

None of those components names a colour. `tone="error"` resolves to
`--haus-color-error-*`, a semantic role, which the brand layer points at a
palette step. So the red in the error Callout, the error Badge and an invalid
Input is the same decision resolved once, and a brand can move it without
touching a component.

<div style={{ display: 'flex', flexWrap: 'wrap', gap: 'var(--haus-space-2)', alignItems: 'center', margin: 'var(--haus-space-4) 0', font: 'var(--haus-type-body-sm-weight) var(--haus-type-body-sm-size)/1.6 var(--haus-font-sans)', color: 'var(--haus-color-ink-secondary)' }}>
  {['tone="error"', 'semantic/color-error-default', 'brand: which ramp step', 'primitive: --haus-cherry-500'].map((step, i) => (
    <span key={step} style={{ display: 'inline-flex', alignItems: 'center', gap: 'var(--haus-space-2)' }}>
      <code style={{ fontFamily: 'var(--haus-font-mono)', fontSize: 'var(--haus-type-mono-size)', padding: '2px var(--haus-space-2)', borderRadius: 'var(--haus-radius-sm)', background: 'var(--haus-color-surface-subtle)', color: 'var(--haus-color-ink-primary)' }}>{step}</code>
      {i < 3 && <span style={{ color: 'var(--haus-color-ink-tertiary)' }}>{'→'}</span>}
    </span>
  ))}
</div>

That is the return on building down through the layers instead of across: the
form above is not styled, it is composed, and it would re-tint as a whole the
moment it is placed inside another brand.
