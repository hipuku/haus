## What this is

haus is the centre of the hipuku portfolio, and the argument it makes is
adoption rather than surface. Three products build on it, and each found a
different half of it useful: <strong>drift</strong> takes the token layer
wholesale and re-themes it, <strong>vault</strong> is haus's complete second
brand, and <strong>core</strong> is migrating onto the scales it never had. The
gaps in haus were found by measuring it against those three, not by guessing.

It is deliberately not a general-purpose kit. Every component here earns its
place by being something the products actually share, and every token resolves
through the four layers below so that a brand change is one file rather than a
search-and-replace.

## The four layers

Colour, space, type, radius, motion: every value enters at the bottom and is
renamed on the way up, so a component never reads a raw number and a brand never
touches a component.

The direction is strict and it is what a theme swap rests on: a component reads
`--haus-color-primary-default`, the semantic layer says that role is the brand's
primary, and the brand layer says which ramp step the brand primary is. Change
the brand file and every component follows, with no component edited. Roles are
declared on `:root, [data-haus-theme]`, so a brand can apply to a subtree and
nest, which is how one page shows two brands at once.

## What is already decided

These are settled, recorded here so a new component does not re-open them. The
decision records in `docs/decisions/` carry the reasoning and the cost.
