# Writing stories

Every component's stories follow one order, so the same information is in the same place for
every component. Include a section only where the component has it. Lay stories out with
`stories/helpers.tsx`, never with inline flex or tables, so spacing and labels match.

| #   | Story                                                                              | Shows                                                                                                                                                                                                                                                                                                                                                                                      | Helper                                               |
| --- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| 1   | `Playground`                                                                       | Every prop as a control.                                                                                                                                                                                                                                                                                                                                                                   | none                                                 |
| 2   | One per visual prop, named after the prop: `Variant`, `Tone`, `Appearance`, `Size` | Each value, labelled with its prop value.                                                                                                                                                                                                                                                                                                                                                  | `Row` + `Item`, or `Stack` for full-width components |
| 3   | `Tone × Variant` (or the two props that compose)                                   | Every combination, so a reader sees that each cell works.                                                                                                                                                                                                                                                                                                                                  | `Grid`                                               |
| 4   | `States`                                                                           | Rest, hover, focus, pressed, disabled, loading, error, whatever the component has, side by side. Hover, focus and pressed are forced with the pseudo-states add-on (`parameters.pseudo`), so they are reviewable in Storybook without a pointer. The add-on needs Storybook's own preview, so under the Vitest run these items render at rest: the screenshots do not cover forced states. | `Row` + `Item`                                       |
| 5   | `Motion`                                                                           | Only for a component that animates. Subtle, expressive and reduced side by side, with a Replay.                                                                                                                                                                                                                                                                                            | `MotionCompare`                                      |
| 6   | `Content`                                                                          | Long text, empty, overflow: what the component does at its edges.                                                                                                                                                                                                                                                                                                                          | `Stack` or `Row`                                     |
| 7   | `In context`                                                                       | The component where a product uses it: a form, a toolbar, a list.                                                                                                                                                                                                                                                                                                                          | none                                                 |
| 8   | Behaviour stories                                                                  | One guarantee each, named as the sentence it proves: "Focus starts on the action". The only stories with sentence names.                                                                                                                                                                                                                                                                   | none                                                 |

## Rules

- **Prop names, not synonyms.** A story about `variant` is called `Variant`, never "Weights" or
  "Appearances". Labels under each item are the prop's value as code would write it.
- **Every story has a one-line description** (`parameters.docs.description.story`), and the
  component has one (`parameters.docs.description.component`).
- **One theme and one motion mode per story.** Light, dark and the motion modes come from the
  toolbar, except in `Motion`, which compares the modes on purpose.
- **A story is a test.** Every story is rendered in light and dark, checked with axe and
  screenshotted. A story that needs a pointer or a timer to show its point is not checkable;
  force the state instead, knowing the forced pseudo-states are checked by eye, not by the screenshots.
