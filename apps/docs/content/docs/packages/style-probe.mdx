title: Style probe

A component's source says what it should look like. The browser says what it does look like, and
those are different questions. `@hipuku/style-probe` answers the second one: it reads an element's
computed style out of a live page and hands it back as values you can compare, so a test can assert
that a Button really is drawing the token it claims rather than that its class list contains a
word.

This is how the Figma parity check and the component audits are measured.

<PackageMeta dir="style-probe" publishedAs="haus-style-probe" />

## Install

```bash
npm install haus-style-probe
```

## Usage

Two halves, split at the browser boundary. `extractRawElements` runs in the page and reads each
element's computed style; the normalising functions run anywhere and turn those strings into values
you can compare, such as `"rgb(37, 99, 235)"` into `#2563eb` and `"0.5rem"` resolved to `"8px"` into
a number. With Playwright, mount a component and read it:

```ts
import { extractRawElements, normaliseElement } from 'haus-style-probe'

const raw = await page.evaluate(extractRawElements, { root: '#probe' })
const [button] = raw.map(normaliseElement)

button.styles.backgroundColor // '#2563eb'
button.styles.padding // [8, 16, 8, 16]
```

Leave out `root` to walk the whole page.
