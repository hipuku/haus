Uncontrolled unless you pass `checked`. `onChange` hands back `(checked, event)`: the boolean because it is what you almost always want, the event because without it there was no way to read `event.target.name` in a form with many checkboxes.

## Anatomy

| Part | Element | What it is for |
| ---- | ------- | -------------- |
| Root | `div` | Holds the row and the messages below it. Takes `className` |
| Row | `label`, `htmlFor` the input | The box and the label text, clickable as one. Takes `controlClassName` |
| Input | `input type="checkbox"` | The real control, visually hidden and never removed from the tree |
| Box | `span`, `aria-hidden` | The drawn box: `marker-box`, `radius-marker`, a `border-width-thick` edge |
| Mark | `svg`, inside the box | The tick, or the bar when `indeterminate` |
| Error | `span`, `role="alert"` | `error`, with the glyph every field's error carries |
| Hint | `span` | `hint`, at the `label-caption` role |

The native input is hidden and the `span` beside it is what gets drawn, so the control keeps every
behaviour a checkbox has and none of the platform's painting.

The box is `border-box`, so its edge sits inside the size `marker-box` names and the drawn box is
that size whatever reset a consumer has. Without that it drew larger in an app with no
`border-box` reset, and the centring below subtracted the wrong number.

The box is centred in the label's first line rather than nudged into place: the offset is that line
box less the box, computed from the type role, so it follows the role rather than one typeface.

The mark is absolutely positioned. In flow it was the box's first in-flow child, so the box took
its baseline from the tick and had none of its own while unchecked, and the whole row moved down
the line the moment it was checked.

## States

| State | Box |
| ----- | --- |
| Rest | `surface-default` with a `border-control` edge |
| Hover | The edge turns `primary-default` |
| Checked, indeterminate | Filled and edged in `primary-default`, with the mark in `ink-inverse` |
| Checked and hovered | `primary-hover` |
| Error | The edge turns `error-default`, and a checked box fills with it |
| Focus | The stepped-out outline, in `border-focus`, or `error-default` while invalid |
| Disabled | `opacity-disabled` on the row |

An unchecked box is an edge and nothing else, so that edge reads `border-control` for the 3:1 WCAG
1.4.11 asks of it (decision 0031). `border-strong`, which it used, is below that.

`indeterminate` has no HTML attribute and can only be set on the node, so it is applied through a
ref after render. A caller's own ref reaches the same node: both are assigned, rather than one
replacing the other.

## Keyboard and screen reader

A native checkbox. Space toggles it, and it tabs as itself.

The hint and the error sit outside the `label` on purpose. Inside it they became part of the
accessible name, so a reader announced the label and the hint as one string instead of a name and a
description. Both are wired through `aria-describedby`, error first, and both are indented to line
up under the label text rather than under the box.

`required` sets `aria-required` rather than the native attribute, as every other field in the
system does: the component owns its error display, and the browser's validation bubble would fight
it. Checkbox was the one doing the opposite.

`error` sets `aria-invalid`, and the error message carries the same glyph every field's error
carries, so it is not told by colour alone (WCAG 1.4.1 Use of Color).

`onChange` hands back `(checked, event)`. The boolean is first because it is what a caller almost
always wants, and the event is there because without it there is no way to read
`event.target.name`, which is how a form with many checkboxes tells them apart. Toggle and
RadioGroup hand back the same pair.

## Motion

The fill and the edge run on the highlight role. A press scales the box on the press role and
releases on layout, as Button's does. The tick draws its stroke on the draw role, which is
instant in subtle and in reduced.

## Decisions

- **`className` lands on the root** (ruling B5). It used to land on the inner `label`, which left
  the outer element unreachable by any prop at all. That is the case that decided B5, and
  `controlClassName` is the named second target the ruling asks for rather than a redirection of
  the one every consumer expects.
- **The hint is a description, not part of the name.** Moving it out of the `label` is the fix, and
  it is also what gave the hint and the error the same indent.
- **An invalid box rings in the error colour.** Input, Textarea and Select each had this rule and
  Checkbox and Radio did not, so an invalid box rang in the brand colour and the error signal
  disappeared the moment it took focus. A token audit could not find it here, because a component
  that never reads a role never appears in a list of components reading it wrongly, which is why
  the rule is now asserted off the API instead (`haus#44`).
- **`useId` is called unconditionally.** Writing `id ?? React.useId()` skips the hook whenever an
  id is passed, so a parent rendering the component with and without one changes the hook count
  between renders.
- **The native input stays in the tree.** Hiding it with `display: none` or replacing it with a
  `div` and a role would cost the platform's own keyboard, forms and autofill behaviour.
