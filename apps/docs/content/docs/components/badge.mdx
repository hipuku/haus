## Install

The registry is for TypeScript projects: with `"tsx": false` in `components.json`, shadcn writes
`.js` and `.jsx` files that still contain TypeScript, and the build fails.

```bash
npx shadcn add @hipuku/badge
```

This adds four files under `components/haus/`: `components/Badge/Badge.tsx`,
`components/Badge/Badge.module.css`, `components/Badge/index.ts`, and `types.ts`, which holds the
tone and appearance vocabulary Badge shares with other components. It also adds `@hipuku/tokens` to
your dependencies.

## Usage

```tsx
import { Badge } from '@/components/haus/components/Badge'

<Badge tone="success">Shipped</Badge>
```

## Anatomy

| Part | Element | What it is for |
| ---- | ------- | -------------- |
| Root | `span`, or the element `as` names | The label, with the tone's background and ink |
| Dot | `span`, `aria-hidden` | A leading marker when `dot` is set, for a status list. It repeats the tone and carries nothing a screen reader needs |

## Tones

`tone` is the meaning. `neutral`, `info`, `success`, `warning` and `error` are the vocabulary
Button and Toast share. `primary` is the brand colour and carries no meaning.

<BadgeTones />

## Keyboard and screen reader

Badge is not interactive and takes no focus. It is read as its text. Colour is never the only
signal: the word carries the meaning, so write one that stands without the colour.

`as` exists so the element matches the content. A count in a definition list is a `dd`, and a
result that updates is an `output`, which a screen reader announces when it changes. A `span` in
either place leaves the meaning out.

## Motion

None. Badge does not animate.

## Decisions

- **`primary` is a tone and not only an appearance.** It is a look rather than a meaning, and has
  no counterpart on Toast. It stays because a brand-coloured badge is something consumers use.
- **`variant` was renamed to `tone` in 1.0.** `variant` meant meaning here and visual weight on
  Button. `BadgeVariant` remains as a deprecated alias.
- **`as` is a closed union**, not a polymorphic generic, for the same reason as Card: four
  elements cover the real uses and the types stay readable.
