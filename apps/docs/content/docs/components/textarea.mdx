## Anatomy

| Part | Element | What it is for |
| ---- | ------- | -------------- |
| Root | `div` | The block: label, field and messages in a column. Takes `className` |
| Label | `label`, `htmlFor` the field | The name, at the `label-field` type role |
| Required mark | `span`, `aria-hidden` | The asterisk, in `error-default`. `aria-required` is what actually says it |
| Field | `textarea` | The control, which draws its own edge, corner and ring. Takes `controlClassName` |
| Error | `span`, `role="alert"` | `error`, with a drawn glyph, at the `label-caption` role |
| Hint | `span` | `hint`, in `ink-secondary` at the `label-caption` role |

This is where it differs from Input. Input has a wrap around its field, because it has adornments
to place beside the value and a box that has to hold them; a textarea has no adornments, so the
edge and the ring are drawn on the element itself. There is no `prefix` or `suffix` for the same
reason: a unit beside a paragraph has nowhere to sit.

The field resizes on the block axis only, and takes a `min-block-size` rather than a height, so
`rows` sets the opening size and the user can grow it from there.

## States

The same set as Input, on the same roles. The edge is the whole of the control's boundary, so it
reads `border-control` for the 3:1 WCAG 1.4.11 asks of it (decision 0031); hover mixes that edge
toward the page's ink; focus turns it to `border-focus` and steps the outline out; an error turns
both the edge and the focus outline to `error-default`, so a field that is wrong keeps saying so
while it is focused.

Disabled takes `surface-disabled`, `border-disabled` and `ink-disabled`, and also turns resizing
off: a control that cannot be typed into should not offer a handle.

The placeholder reads `ink-placeholder`. This is the component that had it wrong: it painted a
placeholder at `ink-secondary`, as dark as a real value, which is the one thing the colour exists
to prevent (`haus#42`).

## Keyboard and screen reader

A native `textarea`. Tab moves out of it rather than indenting, and Enter inserts a line break, as
it does anywhere else.

Focus is `:focus-visible` directly on the element, where Input needs `:has(:focus-visible)` on its
wrap.

The label is a real `label` with `htmlFor`. The hint and the error are wired through
`aria-describedby`, error first, so a reader hears what is wrong before the guidance that was
already there, and the hint is kept rather than replaced. The error carries `role="alert"`, `error`
sets `aria-invalid`, and `required` sets `aria-required` rather than the native attribute, because
the component owns its error display and the browser's validation bubble would fight it.

`controlClassName` lands on the field, for the cases where the control needs styling and the block
around it does not. Ruling B5 keeps `className` on the root, and this is the named second target
that rule asks for.

## Motion

The edge, the focus colour and the outline offset run on the highlight role. The error grows in on
the layout role, as a grid row from `0fr` to `1fr`, so the content below moves rather than jumps,
and the glyph's ring is drawn a stagger step later on the draw role.
