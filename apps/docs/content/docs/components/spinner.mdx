The CSS is a keyframe and is not the point: the contract is whether the wait is announced, and whether it is announced twice when the text beside it already says so. Promoted on evidence (haus#55): all three products built one, plus Button inside haus, and they gave three different answers. One announced nothing at all, one hid itself outright, one was correct. `announcedBy` is that defect turned into a prop, and it takes the text that speaks instead of a boolean, so silencing requires naming what covers it.

## Sizes

`text` sizes to `1em`, so the ring matches whatever text it sits beside rather than picking a step
off the scale. That is the case Button has: a spinner inside a label is a glyph in a line of text,
and a fixed size there is wrong at every size the button is not.

`sm` and `md` take `icon-sm` and `icon-lg`, for a spinner that stands on its own, such as a
loading panel.

## Keyboard and screen reader

Not interactive, and takes no focus.

By default the root is a `status` live region carrying `aria-label`, so a reader is told that
something is happening without the page having to move focus. `label` is defaulted rather than
required: the failure this component exists to stop is a spinner that announces nothing, and a
required prop is one a caller can satisfy with an empty string.

`announcedBy` is for the case where something else already announces the wait, which vault has: a
ring beside the words "Extracting colours" otherwise announces it twice. Passing it drops the role
and the label together and hides the element, because a reader that meets an empty live region
announces the pause rather than the reason.

**Something else announcing it means a live region, not merely visible text.** A span reading
"Extracting colours" inserted beside the spinner is seen and not said, and silencing the spinner
next to it leaves nothing that speaks at all. The region has to be in the document before the wait
begins and take the text when it starts, which is W3C's status-message technique; a region that
arrives already populated is not reliably read.

**That limit applies to the spinner's own region as well**, and saying otherwise would recommend
the thing this paragraph calls unreliable. A Spinner that mounts when loading starts brings its
region and its label in together, so the default is best effort rather than a guarantee: it is
what makes a silent spinner impossible, not what makes an announcement certain. A wait that has to
be announced needs a region the consumer keeps mounted, which takes the text when loading begins.
Where the consumer has one, `announcedBy` names it and silences the spinner, because the two
together say the same thing twice. Where they have none, the default is the better of what is left.

The prop takes the text that speaks instead of a boolean, deliberately: every product that got this
wrong got it wrong by silencing the spinner and putting nothing in its place, and a boolean would
make that the easy thing to write again. The value is also kept on `data-announced-by`, which
nothing reads, so the reason a spinner is silent is visible in the DOM and assertable in a test.

## Motion

One keyframe, a full rotation, running on `motion-duration-emphasis` with `ease-linear` and
repeating indefinitely.

An indefinite animation is the clearest case for `prefers-reduced-motion`, and also the one case
where stopping outright is wrong: a still ring reads as a broken graphic rather than as waiting.
Under both the media query and haus's own `data-haus-motion="reduced"` the ring keeps turning at a
third of its speed. The reduced mode used to take `duration-reduced`, which is zero and stopped
the ring, the exact failure the component was written to avoid.

Under `forced-colors` the ring takes `CanvasText`, so it stays visible in the user's own palette.

## Decisions

- **Promoted on evidence** (decision 0017, `haus#55`). Built independently in all three products
  and once inside haus's own Button, seven call sites, with four separate `.spinner` rules across
  core and drift, and three different answers to the only hard part: core renders an SVG with no
  role, no label and no `aria-hidden`; drift renders a span hidden outright, so a reader waiting on
  a crawl is told nothing is happening; vault gets it right.
- **`announcedBy` takes the text, not a boolean.** The legitimate silent case is real, and the
  shape of the prop is what keeps it from being spent on the illegitimate one.
- **The ring is a border, not an SVG.** A border takes `currentColor` and needs no fill plumbing,
  so a spinner inside a Button is the button's text colour whatever tone that is.
- **Reduced motion slows the ring rather than stopping it.** The alternative is a static arc,
  which reads as a rendering failure.
