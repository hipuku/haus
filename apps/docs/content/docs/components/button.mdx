```tsx

<Button variant="primary" onClick={save}>
  Save changes
</Button>
```

## Variants

`variant` is visual weight. Use one `primary` per view, for the action the view is for.

| `variant` | Use it for |
| --------- | ---------- |
| `primary` | The main action |
| `secondary` | Actions beside the main one |
| `ghost` | Quiet actions in toolbars and dense rows |
| `text` | An action that sits in a line of text |

## Tones

`tone` is meaning, separate from weight, and every tone works at every variant: `neutral`, `info`,
`success`, `warning` and `error`. Use `error` for an action that destroys something.

## Sizes

`md` is the default. `sm` is for dense interfaces, and `lg` meets the enhanced touch target size.

## Links

Give it `href` and it renders an `<a>`. Add `external` for a destination outside the app: it adds
an arrow, and a `_blank` target gets `rel="noopener noreferrer"`.

For a router's link, pass it as the single child with `asChild`:

```tsx
<Button asChild variant="secondary">
  <Link href="/settings">Settings</Link>
</Button>
```

## Loading

`loading` shows a spinner in place of the label. The button keeps its width and its focus, and
it does not run `onClick` or submit its form a second time while it loads.

<Notice tone="info">
`loading` cannot be combined with `asChild`, and that is a type error: a link has no submitting
state to show.
</Notice>

## Accessibility

- A `<button>`, or an `<a>` with `href`, so it works from the keyboard as itself: Enter and Space,
  or Enter on a link.
- The focus outline shows on keyboard focus only, and meets the 3:1 contrast WCAG asks of it.
- A disabled link is really disabled: out of the tab order and not activatable.

<Notice tone="warning">
`loading` sets `aria-busy`, which marks the button as busy but does not make a screen reader say
anything. If the wait has to be announced, put its text in a live region you own.
</Notice>
